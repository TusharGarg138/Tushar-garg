---

## 1. Purpose of Synthetic Examples

The Aeron Systems assignment guidelines require complete transparency regarding AI tooling, including export provenance and schema compliance. This directory serves two specific software engineering and auditing objectives:

1. **Schema Reference**: It defines the standard JSON and JSONL structure expected by automated audit parsers, illustrating how user prompts, agent reasoning, tool invocations, and command outputs are formatted.
2. **Parser Testing**: It provides mock records for testing log-parsing utilities without risking unintended mutation, truncation, or contamination of the genuine session logs located in `ai_logs/original_exports/`.

---

## 2. Synthetic Schema Specification

Authentic agent trajectories generated by Google Antigravity and modern coding assistants adhere to structured JSON Lines (`.jsonl`) formats. Each line is an independent JSON object capturing an individual conversational step.

### Field Definitions

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `step_index` | Integer | Zero-based incremental sequence index of the interaction. |
| `source` | String | Originating entity: `USER_EXPLICIT`, `MODEL`, or `SYSTEM`. |
| `type` | String | Event classification: `USER_INPUT`, `PLANNER_RESPONSE`, `TOOL_CALL`, `TOOL_OUTPUT`. |
| `status` | String | Execution status: `DONE`, `RUNNING`, or `ERROR`. |
| `created_at` | String (ISO 8601) | Coordinated Universal Time (UTC) timestamp of the event. |
| `content` | String / Object | Text content of the prompt, model reasoning, or command output. |
| `tool_calls` | Array of Objects | (Model only) List of invoked tools, arguments, and metadata. |
| `thinking` | String | (Model only) Internal chain-of-thought analysis prior to action. |
